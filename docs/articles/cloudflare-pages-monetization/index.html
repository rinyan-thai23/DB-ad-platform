AI制作 → GitHub → 無料公開

AIで作ったサイトをCloudflare Pagesで無料公開・収益化する方法

最初から独自ドメインやレンタルサーバーを契約せず、1つのサイトに複数ツールをまとめて需要を検証する方法です。広告コードを設置できることと、広告会社の審査に通ることは分けて考えます。

公開・更新: 2026年8月12日

先に結論

無料段階はCloudflare Pages、伸びたら独自ドメイン

GitHub → Cloudflare Pages → pages.devで公開し、初期はアフィリエイトや紹介リンクを中心に検証します。アクセスと利用実績が育った段階で独自ドメインを接続し、このDBから表示広告の候補を選ぶ流れが、費用と審査リスクを抑えやすい方法です。

複数ツールは1つのサイトにまとめる

example.pages.dev/
├─ image-resizer/
├─ character-counter/
├─ json-formatter/
├─ invoice-generator/
└─ guides/

小さなサイトを大量に分けるより、説明記事、FAQ、運営者情報、プライバシーポリシーを1つのサイトに蓄積できます。検索評価や被リンクも分散せず、将来はサイト全体を1つの独自ドメインへ移せます。

Cloudflare Pagesを使う理由

  • GitHubリポジトリと連携し、push後に自動公開できる
  • 静的HTML・CSS・JavaScriptをそのまま配信できる
  • pages.devの無料URLとHTTPSが付く
  • 広告タグ、アクセス解析、ads.txtを配置できる
  • Freeプランは1アカウント100プロジェクト、月500ビルド、1プロジェクト20,000ファイルまで
  • 独自ドメインを後から追加できる

ただし、100プロジェクト作れることと、100サイトへ分散することが有利であることは同じではありません。収益化目的なら、関連ツールをテーマごとにまとめるほうが現実的です。

無料URLの段階で行うこと

  1. 各ツールに固有URLと静的HTMLを用意する
  2. 使い方、入力例、計算根拠、制限、FAQを記載する
  3. 運営者情報、問い合わせ先、利用規約、プライバシーポリシーを置く
  4. 関連サービスのアフィリエイトリンクや紹介リンクを掲載する
  5. 検索流入と実際の利用状況を確認する
  6. 表示広告を試す場合は、DBで「独自ドメイン必須ではない」サービスを優先して個別確認する
重要: pages.devへ広告JavaScriptを設置できても、広告会社がそのサイトを承認するとは限りません。無料URL、コンテンツ量、独自性、サイト所有権、訪問者地域は別々に審査されます。

独自ドメインを取得するタイミング

検索から継続的に訪問者が来る、繰り返し使われるツールがある、紹介リンクのクリックや成果が出る、または広告審査を本格的に受けたい段階が目安です。Cloudflare Pagesは後から独自ドメインを接続できるため、公開基盤を作り直す必要はありません。

独自ドメイン取得後にこのDBを使う

  1. AdSense以外の候補を見る
  2. 独自ドメイン必須を含めて選択肢を広げる
  3. 媒体の推奨言語と、収益化しやすい訪問者地域を確認する
  4. 新しいサイトごとの審査、本人確認、税務手続きを確認する
  5. 最低支払額と日本の銀行への振込を確認する
  6. 個別ページの実収益例と出典を確認する

広告サービスを比較する

掲載候補になりやすいサイト

  • ツールだけでなく、目的と使い方が説明されている
  • 結果の意味や計算根拠が分かる
  • 操作ボタンと広告が明確に区別されている
  • 同じテンプレートの薄いページを大量生成していない
  • スマートフォンでも安全に操作できる
  • 著作権、個人情報、アップロードファイルの扱いが明記されている

確認が必要なサイト

  • 入力欄と実行ボタンしかない単一ページ
  • ブラウザ上で内容が生成され、初期HTMLに説明がほとんどないSPA
  • AI生成文を置いただけで独自の検証や情報がない
  • 画像・PDF・個人情報を送信するが保存方針がない
  • 広告をダウンロードボタンやツール操作に見せる配置
  • 無料サブドメインを広告会社が受け付けるか確認できない

GitHub Pagesを商用公開先にしない

GitHub Pagesはソースコード、ドキュメント、個人ページの公開には便利ですが、オンラインビジネスや商用SaaSを運営する無料ホスティングとしての利用には公式上の制限があります。本記事の流れでは、GitHubはソースコードの保管と更新に使い、公開先はCloudflare Pagesとします。
